# RetrievalManager Caching Implementation Plan

## Overview
Implement FastAPI dependency injection caching for RetrievalManager to avoid expensive re-initialization on every request. This will significantly improve API performance by reusing the same RetrievalManager instance across all requests.

## Problem Statement
Currently, RetrievalManager is being created fresh on every API request, which involves:
- Initializing ChromaDB client connections
- Loading embedding models (HuggingFace)
- Initializing LLM models (OpenAI)
- Creating vector store connections
- Setting up RAG chains

This is expensive and unnecessary since the configuration doesn't change between requests.

## Solution: FastAPI Dependency Injection Caching

### 1. Update Dependencies File
**File:** `src/disney/api/dependencies.py`

**Changes:**
- Add RetrievalManager import
- Create global cache variable for singleton pattern
- Implement `get_retrieval_manager()` dependency function
- Add utility functions for cache management

**New Functions:**
```python
def get_retrieval_manager() -> RetrievalManager
def reset_retrieval_manager()
def get_retrieval_manager_stats() -> dict
```

### 2. Update Routes File
**File:** `src/disney/api/routes.py`

**Changes:**
- Remove manual RetrievalManager creation from all routes
- Replace with FastAPI dependency injection: `vector_manager: RetrievalManager = Depends(get_retrieval_manager)`
- Remove chroma_host and chroma_port parameters from route functions
- Simplify route logic by using cached instance

**Routes to Update:**
- `query_reviews()` - Line 21
- `health_check()` - Line 79  
- `query_reviews_enhanced()` - Line 155

### 3. Add Cache Management Endpoint
**New Endpoint:** `GET /cache-status`
- Provides visibility into cache state
- Useful for debugging and monitoring
- Returns cache statistics

## Expected Benefits

### Performance Improvements
- **Faster Response Times**: Eliminate ~2-3 seconds of initialization per request

- **Cleaner Routes**: Simplified route functions

## Technical Details

### Caching Strategy
- **Singleton Pattern**: One instance per application lifecycle
- **Lazy Initialization**: Created on first request
- **Thread-Safe**: FastAPI handles concurrency
- **Memory Efficient**: No duplicate instances

### Error Handling
- Graceful fallback if cache fails
- Proper logging for debugging
- Cache reset capability for recovery

### Monitoring
